# Agente C · Descargador · 25 de noviembre de 2026

## Resumen

- Tres variantes del calendario por ingreso dejan la bitácora `LEIDA` y generan `CALENDARIO_FALLIDO`. Cuando otro calendario se lee, la tabla queda `PARCIAL`.
- `PENDIENTE` admite `- - -` en Fecha Informe en los lectores actuales. El lector Python anterior al cambio del 12 de noviembre rechazaba ese valor. Se reprodujo el fallo desde el código histórico y se reexportó un control ficticio equivalente.
- Un histórico sin verificar deja su tabla `FALLIDA` si todas las lecturas de esa fuente fallan. Con una fuente mensual incompleta, la creación del ZIP se detiene.
- El aviso de Flow Rust nombra los códigos y sus conteos. Al lado del ZIP queda un JSON anónimo separado del contrato de captura.

## Qué enviar

Puedes renombrarlo a `diagnostico_cobertura.json` antes de enviarlo. Copia el texto del aviso desde «Paquete con cobertura incompleta», con sus códigos y números. Por ejemplo, `CAL_ESTADO_FECHA (1)` indica que una consulta de calendario trae un estado incompatible con Fecha Informe. El número de consulta en el JSON es un ordinal dentro del paquete.

Si ves `CAL_MENSUAL_INCOMPLETO` y Flow detiene la creación, envía el código, el mes o los meses que faltaron y cuántas consultas quedaron verificadas. Si tu versión todavía no genera el JSON nuevo, puedes adjuntar `diagnostico_bitacoras.json` y, si existe, `diagnostico_calendarios.json`. Si el problema parece venir de una versión anterior, indica la versión o la fecha de la compilación si la tienes. Comparte solo esos diagnósticos y conteos anónimos.

## Clasificación de los hallazgos

- **Hechos reproducidos.** La cobertura de bitácoras y calendarios se calcula por fuente. Un calendario fallido sigue siendo visible como incidencia aunque la lectura de sus dos bitácoras termine `COMPLETA`. Un histórico no verificado degrada su propia cobertura.
- **Diferencias declaradas.** Flow Rust crea el JSON hermano y muestra códigos de cobertura, incluido el de lote mensual pendiente en el aviso de rechazo. Flow Python da el error general de lote incompleto. Ambos rechazan la creación en ese caso. Se normalizaron los saltos de línea de fixtures sintéticos para que la regeneración de bitácoras produzca los mismos bytes en Windows y Linux.
- **Inferencia operativa.** Una compilación Python sin el cambio `38fa03d` puede originar `CAL_FECHA_ILEGIBLE` con el calendario de un ingreso `PENDIENTE`. Se ejecutó el lector histórico desde Git y se probó un control ficticio equivalente en Rust. El código también cubre otras fechas ilegibles.
- **Pendiente de evidencia.** Atribuir el caso reportado exige un extracto anónimo de la próxima reproducción. El encargo usó exclusivamente datos sintéticos y el ejecutable histórico no estuvo disponible.

## Riesgos y pendientes

- La ausencia de fallo en el control `PENDIENTE` vigente no permite determinar qué ocurrió en un lote real. Queda pendiente la prueba corta del usuario con su sesión y el extracto anónimo que produzca.
- `CAL_FECHA_ILEGIBLE` por sí solo no identifica la compilación. La versión o una nueva lectura dan contexto adicional.
- El aviso informa las limitaciones acreditadas por el paquete. Para una consulta sin vínculo ni identidad, el diagnóstico de lecturas del lote es la evidencia más directa.
- Cierre en la rama de integración a cargo del coordinador. La aceptación de uso real corresponde al usuario.
