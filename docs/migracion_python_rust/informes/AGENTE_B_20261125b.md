## 5. Hallazgos

**Hechos.**

- Las opciones se guardan con los nombres de Python (`consolidado`, `calendarios`, `historia`, `historico`,
  `historia_en_paquete`, `meses`, `informes`, `fecha_informes`, `pdf_vacias`) y se validan con el mismo criterio.
- «Otra selección» no tiene un error propio en Python: `_alcance` acepta cualquier `seleccion` guardada y sin ella usa el
  lote de bitácoras. Lo que Python sí rechaza —y el oráculo fija— es un `proceso.json` dañado («Elige una carpeta
  «Paquete CSMP …»…) y uno sin alcance («Este paquete no guardó su alcance…»).
- Un paquete cortado se completa en el lugar: el ZIP anterior se conserva como «Captura_CSMP anterior …» dentro de
  `respaldo/`.
- Diferencias del escritor de paquetes (`paquete.rs`, fuera de este encargo) que el oráculo excluye y declara: el
  manifiesto de Rust no lista `escritos`/`historico_proteccion` cuando el paquete no los trae (Python los deja en
  `NO_SOLICITADA`) y agrega la incidencia `CONSOLIDADO_OMITIDO` cuando el lote no es apto.

**Inferencias.** El SITFA ficticio de Rust (`sitfa_ficticio.rs`) solo responde la edición Lite (`prepare`/`search`/
`download`), así que el doble del oráculo vive en las pruebas de `flujo_paquete.rs`: delega `prepare` en `SitfaFicticio`
y sirve listados, bitácoras y calendarios con los mismos documentos sintéticos que el generador de Python. No se tocó
`sitfa_ficticio.rs`.

**Especulación.** Si el usuario usa el flujo con un lote ya apto para consolidado, la incidencia `CONSOLIDADO_OMITIDO`
no aparece; el oráculo la neutraliza en todos los casos.
