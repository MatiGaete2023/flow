## 5. Diferencias y hallazgos, clasificados

### (a) Error de Rust, corregido

1. **Plantilla XLSX sin anchos de columna.** `flow_meta4::plantilla` exigía el bloque `<cols>` y respondía «La plantilla no
   define los anchos de columna»; `validar_plantilla` de Python acepta esa plantilla y `generar` termina bien (un libro
   guardado sin personalizar anchos no trae `<cols>`). Ahora el bloque es opcional: si existe se copia, si no se conservan
   los anchos del libro generado. Cae el caso `plantilla_sin_anchos`, que antes Rust rechazaba.

### (b) Hojas auxiliares con valores distintos, declaradas

1. **`META 4 - actualizado 2026-08.xlsx | Control bitácoras` (al regenerar).** Flow escribe fechas y cifras como texto,
   rotula `OK` donde Python pone `COMPLETA` y no agrega la línea «Regenerado desde Registros.xlsx revisado». Es la misma
   hoja ya declarada para la generación (D-13).
2. **`Registros.xlsx | ERRORES_Y_ADVERTENCIAS` (al regenerar).** Python conserva la hoja del libro revisado; Flow la
   reescribe con sus propios avisos (incluida la línea de regeneración).
3. Las **9 hojas declaradas** de la generación no cambian (`HOJAS_DECLARADAS`): la prueba falla si aparece otra o si alguna
   deja de diferir.

### (c) Ambigüedad o comportamiento de Python, no se cambia

1. **Fecha de emisión al regenerar.** `regenerar` de Python toma `mes_emision` del reporte (`AAAA-MM`) y escribe el día 1;
   Flow guarda la fecha de emisión completa y conserva la fecha de corte (31-08 frente a 01-08). El oráculo normaliza esa
   celda y afirma las dos formas, para no ocultar el resto de la hoja.
2. **Filas que no son FAE ni Residencia.** Python las descarta del candidato: no quedan ni en Registros ni en META 4. Flow
   las conserva en `Registros.xlsx`, las excluye de la planilla y las cuenta en `fuera_de_meta4` (el propio libro lo
   advierte). El oráculo cuenta esas filas aparte: 1 en `programa_fuera_de_fae_y_residencia`, 0 en el resto.
3. **Plantilla con celdas combinadas o dibujos.** `validar_plantilla` de Python la acepta; Flow la rechaza para no alterar
   los datos al reestilizar. Diferencia declarada y probada (el oráculo exige Python sí / Rust no).
4. **Dónde se valida la plantilla.** Python valida en la interfaz (`validar_plantilla`) antes de generar; Flow valida al
   publicar. Con (a) corregido, el resultado observable coincide salvo el punto 3.

## 7. Riesgos y pendientes

- **Reproducción del oráculo:** los XLSX que van en `meta4.json` se guardan sin comprimir y con `docProps/core.xml` fijo
  para no depender de openpyxl ni del zlib del ejecutor; el run 45656558813 confirmó que Windows + Python 3.12 regenera
  bytes idénticos a los versionados. Si cambia la versión fijada de openpyxl, hay que volver a correr el generador.
- **Tamaño:** `meta4.json` pesa 1,67 MB (antes 811 KB). Si molesta, se puede mover la parte de regeneración a otro JSON y
  declararlo en el workflow (hoy solo se regenera `meta4`).
- **`volcado::volcar` no lee libros de openpyxl** (punto de hallazgos). Si otro oráculo necesita comparar un libro escrito
  por Python, primero hay que ampliar esa expresión regular; no se hizo por estar fuera del reparto.
- **Plantillas con celdas combinadas:** hoy Flow las rechaza con un mensaje claro. Si el usuario usa plantillas con celdas
  combinadas, habría que portar el manejo de combinaciones (hoy no se copian dibujos, macros ni vínculos).
- Sin cambios de firma de funciones compartidas: `meta4::calcular`, `flow_meta4::salida::*`, `flow_meta4::regenerar::*` y
  `paquete::*` quedan igual; `flow_meta4::plantilla` no expone nada nuevo.
- Nada pendiente del usuario en este encargo; el acta de uso real sigue siendo suya.
